# 额度控制规则

生效于 2026-11-13，适用于后续会话。用户当轮明确要求优先。目标是减少重复上下文、无效迭代和不必要并行，保持交付质量；本规则不改变账户计费，也不承诺固定节省比例。

## 任务与并行

- 默认 1 个主会话、0 个子智能体。设计、美术、数值、工程、QA 是职责标签，不需要同时在线。过去要求多会话制作，不作为今后自动启动并行的持续授权。
- 用户本轮明确要求并行时才启用。未指明数量时最多 1 名子智能体；明确指定数量时遵从用户要求。用户同一任务已经授权的必要工作不重复询问。
- 子任务提供简短目标、允许写入路径、必要契约、验收与交付格式；默认不继承完整聊天。父子会话不重复探索同一问题，不同时写同一文件。
- 一次交付一个可验收目标，例如一个完整容器搜索流程，或一个区域的视觉样板。范围明确后完成实现、验证和交付，不顺带启动额外系统或大范围重构。

## 上下文与检索

- 开始读取 CONTEXT 与 STATUS；随后按具体问题读取相关函数、配置和领域文档。历史证据、完整路线和旧交接按需打开。
- 先用 rg 定位，再读取命中片段。独立查询可批量执行；避免把整份源码、日志或大量无关工具说明送入上下文。
- 技能先按目录判断是否适用，真正使用时才读对应 SKILL.md；不因为关键词相近而连续读取多个完整技能。
- 开新会话携带简短交接：当前目标、基线、相关路径、已测结果、未完成项；不粘贴整段聊天。项目规则和领域事实集中维护，其他位置引用链接。

## 模型、速度与用量

- 不擅自修改用户账户或全局模型、推理、速度设置，不自动提高到最高推理或 Fast/Ultrafast。只能控制当前工具明确支持的设置；无法调整时直接说明。
- 可选择时，常规实现采用适合编码的常规模型与中等推理；清晰的小任务采用较轻模型；复杂诊断、契约设计和难以复现的问题才提高推理强度。降低重试总量比单纯降低单次成本更重要。
- 不默认轮询额度。用户询问或明确约定预算时读取；阶段前后快照仅用于参考，账户级百分比不能当作单一任务或某个子智能体的准确账单。
- 不承诺“本任务只耗几个百分点”或“少输出文字就按比例省额度”。控制可观察的任务范围、调用数量和重复工作。

## 纯程序生成的制作约束

- 用户已明确要求整个游戏的内容资源仅用程序创造，此项是持续制作约束，不是临时节省额度的偏好。除非用户之后明确更改，不使用图像或三维生成服务，不导入现成模型、贴图、图标、动作或音频素材。
- 模型采用参数曲面、挤出、网格构造、骨骼和程序动画；材质与图标采用 Canvas、DataTexture 或着色器；音效采用程序合成。优先运行时按种子生成，共享缓存并复用生成器。通用引擎、代码库和开发工具可继续使用。
- 联网可查阅技术文档、学习制作方法和观察参考，不把允许联网解释为允许下载游戏内容资产。
- 先确定资产用途、尺度、UV、材料类型和验收机位，再编写生成器。程序材质要按物体结构制作磨损、污迹和材料分区，不能只叠随机噪声。几何轮廓、接触和动画问题分别用网格或动作修改解决。
- AI 颜色图、面部图及其派生法线/粗糙度为历史实现，P0 已移除运行加载与打包引用，用程序 DataTexture 替换，保留几何、UV 与挂点；证据见 [程序材质记录](art/PROCEDURAL_PASS.md)。原始图源可留作非运行参考，不为清理资源删除用户资料。
- 用户于 2026-11-13 明确暂缓包体、生成耗时和内存验证，本阶段不开展这些专项采样和相关优化。保留必要的类型/构建、功能回归与画面检查；构建工具自行显示体积不等于需要继续做包体分析。不把页面宣称的 1.4 MB 作为已验证的工程预算。

## 验证与交付

- 纯文档改动检查内容与链接，不启动全项目构建、浏览器或截图套件。
- 代码修改先执行受影响模块的必要检查；共享契约、跨模块行为或阶段集成再做适当的完整测试与生产构建。已通过后，仅有新修改、失败或未解决疑点时扩大或重复验证。
- 视觉改动先固定少量关键机位，每轮只复拍受影响画面；验收时保留实机证据。无变化的画面不重复生成整套截图。
- 本地脚本正常执行，模型只读取结果摘要与必要错误片段。不要为节省输出而隐瞒失败，也不要为证明工作量而反复读取完整成功日志。
- 每次仅维护相关领域文档及 STATUS 的简短增量；最终说明任务、改动、验证、限制和下一步，已有细节用链接引用。

## 当前材质事实

P0 后环境、角色、武器材质均在代码中生成。历史 AI 图源与派生文件保留在 `assets/` 作为非运行参考；没有将图片转为 base64 或数组。生产实测图片请求为 0，证据见 [程序材质记录](art/PROCEDURAL_PASS.md)。材质来源不代表画面质量已被认可，继续以几何、材料分工、尺度和实机检查为准。
